## Command contract

**[SPEC]** `skills-mgr ai trigger-test --scope SCOPE --saved` estimates the
existing scope's saved A7 prompts without sending a provider request. Scope
defaults to `global`; `all` is refused. This first CLI slice accepts saved
prompts only, at most 120 per run, with repeats 1–5. A saved set may contain
500 prompts, but a larger-than-120 set must be reduced before this command.
Missing expected skills are errors and never silently removed from the sample.

`--run` explicitly spends against the existing AI configuration, environment
credentials and token caps. No key argument is accepted. No skill is changed
and the rebuildable SQLite index is not initialized. Completed runs and usage
use the existing private JSON history and ledger, including its 50-run retention.
The selected listing, normalized prompts and resolved configuration are captured
once; baseline preflight and transmission use that same in-memory snapshot.
The full captured routing request plan is estimated against run/day caps before
its first call. These are token estimates rather than billing ceilings. Since
2026-11-13 each call is also admitted against recorded usage plus every live
in-flight reservation (`<data>/ai/reservations.json`, shared across processes),
so concurrent independent runs can no longer jointly exceed the daily cap; the
cap still bounds estimated input, not provider billing.

`--seed N` (default 0, initial value 0–4294967295) controls sorted-listing
permutations with seeds `N`, `N+1`, … for repeated passes. Prompt order remains
the saved order. Values of later repeat seeds may exceed the initial-value
range. The seed is not sent to the provider, and provider outputs can vary.
Runs record canonical SHA-256 fingerprints of ordered prompt text/expected
pairs, sorted listing names/descriptions, and endpoint, with a listing snapshot,
provider/model labels, seed, repeat count and routing-contract version.

## Baseline and gate

**[SPEC]** `--baseline RUN_ID` pins a retained run. Without it the CLI considers
the newest modified saved-prompt trigger run for the scope within the newest
50 trigger artifacts, using identifier order to break modification-time ties.
Malformed candidate files are errors, never skipped to find an older green
result. Explicit IDs are recommended for CI and concurrent writers. No baseline
is required for an ordinary estimate or ungated first run.

`--fail-on-regression` requires `--run`. Before a provider request, it requires
a complete baseline with matching scope, ordered prompts, provider, model,
endpoint, seed, repeats and evidence version. Legacy runs lacking fingerprints,
partial/disconnected runs, invalid or missing answers, inconsistent counts and
damaged snapshots cannot be baselines. Listing changes are allowed because
they are the intervention, and `listing_changed` discloses them.

Counts are recomputed from every prompt's repeated choices, rather than from
stored hit rates. Each expected skill and the expected-none group has integer
`hits` and `answers`. Any decline in hits for the same denominator is an observed
regression; this includes more false triggers on negative prompts. It is an
operational sample gate, not a statistical-significance or real-agent claim.
Incomplete current results fail even without `--fail-on-regression`.

AI artifact reads refuse non-regular files, final symlinks and linked private AI
subdirectories, and cap each file at 16 MiB. Oversized files are rejected before
allocation and the descriptor read is also capped if a file grows. This bound
covers ASCII-escaped JSON for 600 full Unicode descriptions and 500 saved prompts;
a 2 MiB bound failed a real writer/reader round trip at those supported limits.
The private data directory remains the filesystem authority; these checks do not create a sandbox against the
same OS account.

## Machine output and exit codes

**[SPEC]** `--json` writes one envelope to stdout:

```json
{"schema_version":1,"command":"ai trigger-test","status":"estimate","result":{},"comparison":{}}
```

Successful reports include the full result and comparison status (`missing`,
`not-run`, `incomparable`, or `compared`). Operational errors have `status:
"error"` and `{error: {code, message}}`; incomplete observations retain their
result with `status: "incomplete"`. A measured decrease is `status: "regression"`.
An ungated decrease still exits 0, while its report discloses the regression.
Exit 0 means a completed allowed operation; 1 means operational error,
incomplete evidence, or a failed requested gate; 2 means usage error; 130 means
interrupt. Errors before handler dispatch, argparse usage errors and interrupt
messages retain the CLI's text stderr behavior, including in JSON mode.

JSON and saved runs include prompt text and listing descriptions. Keep these
artifacts and CI logs private; hashes of predictable prompts are not anonymous.
Credentials are not included. Human-readable text sanitizes terminal controls.

## CI recipe

**[NOTE]** Configure the existing AI settings and saved prompt set in a private,
ephemeral data base. `--data-dir BASE` resolves to `BASE/skills-manager` as for
the rest of the CLI. Supply provider credentials through existing environment
variables or the existing settings flow. Keep a baseline artifact under
`BASE/skills-manager/ai/runs/<RUN_ID>.json`; old pre-A14 runs cannot be used.
The scope's installed skill tree must also be present.

```sh
# Estimate first; sends nothing.
skills-mgr --data-dir "$CI_DATA_BASE" ai trigger-test --scope claude-code \
  --saved --seed 17 --repeats 3 --json > estimate.json

# Bootstrap an intentional baseline when none exists, without a gate.
skills-mgr --data-dir "$CI_DATA_BASE" ai trigger-test --scope claude-code \
  --saved --seed 17 --repeats 3 --run --json > baseline-result.json

# CI comparison after installing the candidate skill listing.
skills-mgr --data-dir "$CI_DATA_BASE" ai trigger-test --scope claude-code \
  --saved --seed 17 --repeats 3 --baseline "$BASELINE_RUN_ID" \
  --run --fail-on-regression --json > candidate-result.json
```

Preserve exit status when invoking this in a pipeline. Keep the chosen baseline
and prompt set as explicit private artifacts; the manager's history retention
can remove old runs. This command is opt-in and no paid provider is called by
the repository's ordinary CI workflows.

validated. Empty, one-prompt, over-limit 10,000-prompt and maximum Unicode

input/configuration snapshot; explicit baseline IDs avoid automatic-history
ordering assumptions. Interrupted/partial or corrupt observations cannot pass
the gate; completed calls may still cost tokens. Budget estimation restores its
